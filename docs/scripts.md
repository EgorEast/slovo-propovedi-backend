# scripts — CLI-скрипты

Служебные скрипты репозитория (`scripts/`), запускаемые через `npm run <имя>` или напрямую `node scripts/<имя>.mjs`.

## Скрипт массовой загрузки проповедей — `scripts/upload-sermons.mjs`

Bulk-загрузка папки MP3-проповедей в API: каждый файл загружается как файл в MinIO (`POST /files`), затем создаётся проповедь (`POST /sermons`) с `audioUrl` и ссылкой на плейлист. **Одна папка = один плейлист.**

Запуск:

```bash
npm run upload-sermons -- <путь-к-папке> [флаги]
# или напрямую:
node scripts/upload-sermons.mjs <путь-к-папке> [флаги]
```

Чистый Node.js ≥ 20 (ESM): используется встроенный `fetch`, `FormData`, `Blob`; новых зависимостей не добавляет. Название плейлиста выводится из имени папки (отбрасывается ведущий номер `N. `), файлы сортируются по ведущему номеру в имени (порядок в плейлисте = порядок загрузки).

### Формат имени файла

`<Номер>. <Название проповеди>. <Книга> <глава> <стихОт>-<стихДо>.mp3`

Примеры:

| Имя файла | Название | Книга | Глава | Стих |
|---|---|---|---|---|
| `01. Свидетельства о пришествии Мессии (часть 1). Марка 1 1-3.mp3` | `Свидетельства о пришествии Мессии (часть 1)` | `Марка` | `1` | `[1, 3]` |
| `09. Власть прощать грехи. Марка 2 1-12].mp3` | `Власть прощать грехи` | `Марка` | `2` | `[1, 12]` |
| `13. Как противостоять законничеству. Филиппийцам 3_1.mp3` | `Как противостоять законничеству` | `Филиппийцам` | `3` | `1` |
| `01. Семь отличительных черт книги Откровение (Отк.1,1-3).mp3` | `Семь отличительных черт книги Откровение` | `Отк` | `1` | `[1, 3]` |
| `02. Духовный портрет христианина, способного прощать. Филимону 1-7.mp3` | `Духовный портрет христианина, способного прощать` | `Филимону` | `1` | `[1, 7]` |

Допускаются разные разделители (пробел, точка, подчёркивание), хвостовой «мусор» без цифр (`]`, `(готовое)`), буквенные пометки стихов в скобках (`2 5(б)-6(а)` → стих `[5, 6]`), а также одноглавые книги без номера главы (Филимону, Иуды и т.п. → глава `1`). Файлы без ссылки на Писание (только название) загружаются с `book = chapter = verse = null`.

Ведущий номер трека (`01.`, `12)`, `3]`) отбрасывается из названия. Голая цифра без разделителя (`.`/`)`/`]`/`_`/`-`) — это НЕ номер трека: названия вроде «7 слов со креста» сохраняют ведущую цифру.

Что распознать не получается и помечается как «не распознано» (пропускается, перечисляется в итоге):

- диапазон стихов, пересекающий главы (`Иоанна 18 39 - 19 16` — в модель API можно сохранить только один `chapter`);
- имя файла, содержащее только ссылку на Писание без названия проповеди и книги (например `Иоанна 18 39 - 19 16.mp3` без префикса `<Номер>. <Название>`) — «Имя файла содержит ссылку на Писание без названия проповеди и книги»;
- несколько диапазонов стихов через запятую (`Иоанна 18 12-14, 19-24`);
- отсутствие разделителя между главой и стихами (`Луки 724-30`).

### Флаги

| Флаг | Описание |
|---|---|
| `--api <url>` | базовый URL API (по умолчанию `https://api.slovo-propovedi.ru`) |
| `--username <str>` | имя пользователя (приоритет: флаг > `SP_USERNAME` > интерактивный ввод) |
| `--artist <str>` | исполнитель проповедей (по умолчанию «Андрей Вовк») |
| `--artwork <str>` | URL обложки (по умолчанию пусто; обложки правятся в админке) |
| `--dry-run` | показать план без единого сетевого запроса (без логина) |
| `--no-skip-existing` | всегда загружать файлы, игнорируя дедупликацию по названию |
| `-h`, `--help` | справка |

Пароль флагами/переменными окружения НЕ передаётся: он запрашивается только
интерактивно и скрыто (`--password` и `SP_PASSWORD` не поддерживаются — такой
запуск завершится ошибкой «Неизвестный флаг»). Это гарантирует, что пароль не
попадёт в историю команд. Имя пользователя можно передать флагом `--username`
или переменной `SP_USERNAME`, иначе оно тоже запросится интерактивно.

### Поведение

1. Guard-клаузы: `--help` → справка (exit 0); нет папки / папка не существует / не папка → ошибка (exit 1); нет mp3 → ошибка (exit 1); ни один mp3 не распознан → ошибка (exit 1) до любого сетевого запроса (плейлист не создаётся).
2. Вход по JWT (срок действия access-токена ~30 минут). Если во время загрузки сервер вернул `401` (токен истёк на длинном прогоне), скрипт **тихо перелогинивается** теми же учётными данными (без повторного ввода) и повторяет текущую операцию один раз. Если `401` повторяется после перелогина — fail-fast с ошибкой (exit 1).
3. **Дедупликация по названию проповеди (не по имени файла).** После поиска/создания плейлиста скрипт перебирает все проповеди в базе (курсорная пагинация `GET /sermons`) и строит карту «название → существующие проповеди». Для каждого файла:
   - нет совпадения → файл загружается как сегодня (`POST /files` + `POST /sermons` с `playlistsIds=[playlistId]`);
   - ровно одно совпадение и оно уже в целевом плейлисте → «⏭ уже существует и в плейлисте», запросов нет;
   - ровно одно совпадение, но в целевом плейлисте его нет → `PATCH /playlists/:id` с `sermonsIds` = текущий упорядоченный список + id существующей проповеди (добавление в конец сохраняет порядок файлов); файл **не** загружается;
   - несколько совпадений с одним названием → предупреждение со списком id, файл пропускается (ни загрузки, ни прикрепления);
   - проповеди, созданные в текущем прогоне, тоже попадают в карту — дубли внутри одной папки пропускаются.
   `--no-skip-existing` = старое поведение: всегда загружать и создавать, дедупликацию игнорировать.
4. Любая ошибка запроса в цикле загрузки останавливает скрипт (fail-fast, exit 1); при повторном запуске прогресс продолжится благодаря дедупликации по названию.
5. Не распознанные файлы и не-mp3 файлы — предупреждения, не ошибка (итог, exit 0), но только если хоть один mp3 распознан.
6. **Осиротевшие файлы в MinIO:** если `POST /files` прошёл, а `POST /sermons` упал (сеть, сервер), аудио остаётся в хранилище без проповеди. Повторный запуск загрузит файл заново — старый файл останется в MinIO (почистить можно вручную).
7. **Dry-run не отражает дедупликацию:** он делает ноль запросов и не знает, какие названия уже есть в базе, поэтому «запланировано к загрузке: N» — верхняя граница; реальный прогон может загрузить меньше (часть пропустится/прикрепится как существующие).

### Примеры

Dry-run (план, без сети):

```bash
npm run upload-sermons -- "/путь/к/папке" --dry-run
```

Продакшен (по умолчанию `https://api.slovo-propovedi.ru`, имя пользователя из флага, пароль интерактивно):

```bash
npm run upload-sermons -- "/путь/к/папке" --username admin
```

Локальный dev-сервер:

```bash
npm run upload-sermons -- "/путь/к/папке" --api http://localhost:3000
```

Имя пользователя через переменную окружения (пароль всё равно интерактивно):

```bash
SP_USERNAME=admin npm run upload-sermons -- "/путь/к/папке"
```

Без `--username`/`SP_USERNAME` скрипт спросит имя и пароль интерактивно (пароль вводится скрыто).
